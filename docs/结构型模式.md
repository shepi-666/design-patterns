# 结构型模式

结构型模式描述如何将类或者对象按照某种布局组成为更大的结构，分为类结构模式和对象型结构模式。前者利用类或者继承机制来组织接口和类，后者采用组合或者聚合来组成对象。

## 代理模式

给某个对象提供一个代理以控制该对象的访问。代理对象作为目标对象和访问对象的中介。

按照代理类生成的时机不同，分为**静态代理**和**动态代理**。

* 静态代理：编译时期产生
* 动态代理：运行动态生成

### 结构

代理（Proxy）模式分为三种角色：

* 抽象主题（Subject）类
* 真实主题（Real Subject）类：最终要引用的对象
* 代理类(Proxy)

### JDK动态代理

Java中提供了动态代理类`Proxy`，提供了一个创建代理对象的静态方法（`newProxyInstance`）获取代理对象。

ProxyFactory 是代理类吗？

是工厂类，提供了一个工厂方法，来获取代理类。

JDK动态代理的<u>执行流程</u>：

1. 客户端通过代理对象调用`sell()`方法
2. 根据多态的特性，执行的是代理对象`$Proxy0`的`sell()`方法
3. 代理类`$Proxy0`中的`sell()`方法调用了`InvocationHandler`接口的子实现类对象的`invoke()`方法
4. `invoke()`方法通过反射执行了真是对象所属类`TrainStation`中的`sell()`方法

### CGLIB动态代理

如果没有定义相对应的接口，只能使用CGLIB代理实现。

不能对声明为`final`的类或者方法进行代理，因为CGLIB动态生成目标类的子类。

### 优缺点

**优点**

1. 中介和保护作用，保护被代理的对象
2. 扩展目标对象的功能
3. 将客户端和目标对象分离，降低耦合度

**缺点**

* 增加了系统的复杂度

### 使用场景

**远程（Remote）代理**

RPC的实现原理。

**防火墙（Firewall）代理**

VPN原理。

**保护（Protect or Access）代理**

控制对一个对象的访问。



## 适配器模式

将一个类的接口转换为客户希望的另一个接口，使得原本的接口由于不兼容而不能一起工作的那些类可以一起工作。

适配器模式分为类适配器和对象适配器，前者类的耦合度比后者高。

### 结构

**目标接口**

当前系统业务期望的接口，可以是抽象类或者是接口

**适配者类**

被访问和适配现有组件库的组件接口

**适配器**

一个转换器，将适配者转换为目标接口。

* 旧的系统和新系统接口不一致
* 使用第三方组件接口定义和本方的需求不一致

## 装饰者模式

### 概述

在不改变现有对象结构的情况下，动态地给对象增加一些职责，即增加**额外功能**的模式。



### 结构

* **抽象构建角色**：抽象接口，以规范准备接收附加责任的对象
* **具体构建角色**：实现抽象构件，通过装饰角色添加一些其他的职责
* **抽象装饰角色**：继承或者实现抽象构件，并包含具体的实例，可以通过其子类扩展具体构件的功能
* **具体装饰角色**：实现抽象装饰的相关方法，并给具体构件对象添加附加的责任

![image-20250810203028267](https://shepi-1308499968.cos.ap-chengdu.myqcloud.com/img/image-20250810203028267.png)

 **优点**

* 带来比继承更加灵活的扩展功能，使用更加地方便，可以通过组合不同的装饰者对象来获取具有不同行为的多样化的结果
* 装饰者和被装饰者不会耦合

### 使用场景

1. 系统中存在大量的独立扩展，不能定义的大量的子类
2. 类定义不能被继承
3. 在不影响其他对象的情况下，以动态、透明地方式给单个对象添加扩展功能



### 代理模式和装饰者模式的区别

**相同点**

* 都要实现与目标类相同的业务接口
* 两个类都要声明目标对象
* 都可以在不修改目标类的前提下增强目标方法

**不同点**

|                        | 代理模式                                 | 装饰者模式                 |
| ---------------------- | ---------------------------------------- | -------------------------- |
| 目的                   | 保护和隐藏目标对象                       | 增强目标对象               |
| 获取目标对象构建的地方 | 代理类内部创建目标对象，以此隐藏目标对象 | 外界传入，通过构造方法传递 |
